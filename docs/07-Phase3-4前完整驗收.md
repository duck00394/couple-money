# Phase 3-4 前完整驗收（Phase 1 ～ 3-3）

沒有修改 schema，沒有新增 migration。以下是驗收範圍與修正的問題。

## 驗收方式

| 項目 | 做法 |
|---|---|
| 權限與帳本隔離 | `tests/integration/audit.test.ts`「驗收 A」：兩個帳本、直接呼叫 service（不經畫面），涵蓋交易／帳戶／搜尋／退款／轉帳／固定支出／基金／目標／任務／刪除申請 |
| 財務一致性 | 「驗收 B」：基金指定金額的不變式、任務獎金未入金不是現金、信用卡、餘額／欠款／統計三邊比對 |
| 並發 | 「驗收 C」：同時修改／刪除交易、結算、轉帳、退款、投入基金、修改基金、打卡、刪除申請、產生固定支出 |
| 金額與日期極端值 | 「驗收 D」：0／負數／超上限／小數、除不盡的分帳、自訂金額、轉帳邊界、全額退款、月底與閏年 |
| 手機 UX | `tests/e2e/ux-audit.ts`：iPhone 13（390×664）與 iPhone SE（320×568）逐頁檢查水平溢出、主要按鈕是否被導覽列蓋住、長文字破版 |
| 回歸 | Phase 1 → 2 → 3-1 → 3-2 → 3-3 全流程 E2E（兩支手機不同尺寸）＋ 既有單元／整合測試 |

## 修正的問題

### 會造成錯帳或資料不一致

1. **基金指定的錢可以被一般支出花掉**：earmark 檢查原本只在轉帳與基金投入做。改成不變式「帳戶餘額 ≥ 已指定給基金」，在記帳的建立、修改、刪除後都檢查（基金支出因為同時扣額度所以不受影響）。
2. **刪除任務後，尚未入金的獎金與尚未抵扣的懲罰還留著**：基金頁會顯示不存在的金額，而且基金再也刪不掉。改成刪除任務時一併收回（已入金的是真的錢，保留）。
3. **固定支出的修改／停用／刪除沒有鎖**：另一半剛產生完記帳、我按儲存 → 應付日被舊值蓋回去 → 那一期已經產生過，之後永遠產生失敗。改成鎖定帳本 + 交易內重讀 + `updatedAt` 樂觀鎖。
4. **新增帳戶沒有防重送**：連點兩下會多一個帳戶與一筆期初餘額。改成帶 `clientRequestId`，第二次會撞唯一鍵並整筆回滾。
5. **停用／啟用帳戶會把名稱覆蓋回畫面上的舊值**：改成只更新有送出的欄位。
6. **任務／基金／目標的編輯沒有樂觀鎖**：任務還會誤報「只有建立者可以修改」、已刪除的里程碑復活。四種設定都加 `updatedAt` 比對。
7. **漏做懲罰用交易外讀到的舊設定**：`applyMissedPenalties` 改成鎖定後才讀任務。
8. **建立任務沒有鎖**：基金同時被刪除時，任務會指向已刪除的基金。改成鎖定後在同一個交易內驗證。
9. **結算沒有驗證成員**：加上「結算對象必須是帳本成員」。
10. **獎金入金可以從信用卡轉出**：補上與轉帳相同的信用卡限制。
11. **固定支出的某一期被刪除後再按產生，會顯示成功但什麼都沒產生**：改成明確跳過那一期並說明。

### 權限與錯誤處理

12. **server action 的 `getAppContext()` 在錯誤攔截之外**：帳本狀態改變時會直接丟出例外變成空白畫面。改成在 `toActionState` 內取得；同時讓 `toActionState` 用 `unstable_rethrow` 放行 `redirect()`／`notFound()`。
13. **沒有中文的找不到／錯誤頁**：新增 `(app)/not-found.tsx`、`(app)/error.tsx`、根目錄同款，以及換頁骨架 `loading.tsx`。
14. **唯讀成員在瀏覽目標頁時會寫入資料庫**：`listGoals` 的自動完成改成只在有編輯權限時、而且只更新仍是「進行中」的那一列。連結基金的目標也不再顯示會被自動覆蓋的「改回進行中」按鈕。
15. **打卡把任何唯一鍵衝突都說成「今天已經打卡過了」**：只在真的撞到打卡唯一鍵時才這樣說。

### 顯示與手機操作

16. **詳細頁沒有底部導覽 → 走不出去**：導覽列改成每頁都在，表單送出列固定在導覽列上方（`.sticky-submit-bar`）。
17. **帳戶頁把 `<form>` 放在 `<p>` 裡**：HTML 不合法會造成 hydration 錯誤，改成 `div`。
18. **帳戶頁小計漏算停用帳戶**：停用帳戶裡的錢仍然是真的，小計要一起算。
19. **期初餘額／餘額調整沒有正負號**：現金 +$5,000 與信用卡未繳 $5,000 原本長得一樣。
20. **記帳列表的「當天小計」在還沒載完時會少算**：最後一天若還沒載完就不顯示小計。
21. **退款清單只看最近 60 筆**：先排除已全額退款的消費再取 60，比較舊但還能退的不會消失。
22. **其他**：長備註／長名稱破版、轉帳與退款在 12:00 不顯示時間、固定支出設定已刪除時的連結會 404、基金投入的「超過上限」提示用浮點數比較、登出可連點、重複按鈕沒有可分辨的名稱、固定支出開始日期可留空且預覽顯示錯誤、從記帳頁「記一筆」後回到首頁看不到剛記的那筆。

## 驗收後的產品規則定案

- **基金支出動用哪個帳戶的額度 → 使用者明確指定（採用 B）**：記帳選了基金之後，一定要再選「基金動用來源」。
  系統不會自動挑一個額度夠的帳戶，也不會偷偷產生轉帳。額度不夠時直接擋下並說明要改選哪裡。
  實作在 `syncFundExpense`（`src/server/services/funds.ts`），`pickAllocationAccount` 已移除。
  資料模型不需要改：`FundTransaction` 已經同時記錄 fundId（哪個基金）、accountId（動用誰的額度）、
  transactionId → payments[0].accountId（實際付款帳戶）。
- **期初餘額調整 → 需要，但這次不實作**：設計比較見 `docs/08-餘額調整設計分析.md`（建議 A：ADJUSTMENT 交易，不改 schema）。
- **跨帳本網址的 HTTP 狀態碼 → 保留目前的骨架／串流 UX**：維持 200 + 中文「找不到這筆資料」。
  已補上驗證：畫面與原始 HTML／RSC payload 都不會出現對方的資料；跨帳本 id 與根本不存在的 id
  回傳完全相同的錯誤訊息（不會洩漏「這個 id 是否存在」）；server action 仍然擋在 service 層。
