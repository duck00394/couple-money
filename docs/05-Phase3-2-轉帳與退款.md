# Phase 3-2 帳戶間轉帳與退款

資料表沒有變動（`TxType.TRANSFER`／`REFUND`、`Transaction.relatedId` 在 Phase 1 就存在），所以沒有新的 migration。

## 一、帳戶間轉帳

入口：記帳頁「🔁 轉帳」、或記一筆／轉帳／退款三個分頁。

| 欄位 | 說明 |
|---|---|
| 來源帳戶 | 信用卡不能當來源（繳卡費是「轉入」信用卡） |
| 目的帳戶 | 可以是共同帳戶、個人帳戶、信用卡 |
| 金額、日期、時間、備註 | 時間選填，沒填就記當天中午 |

分錄：來源帳戶 −金額、目的帳戶 +金額，Σpayment = 0、沒有分帳。因此轉帳

- 不算收入、不算支出（搜尋統計另外列「轉帳 N 筆」）
- 不影響誰欠誰、不影響分帳
- 之後的預算也不會把轉帳算進去（預算只看支出／退款）

### 可以轉出多少

**可自由使用 = 帳戶餘額 − 已指定給基金**，轉出金額不能超過它。

```
共同帳戶  餘額 $30,000
          已指定給基金 $20,000
          可自由使用 $10,000   → 最多只能轉出 $10,000
```

這樣「基金指定的金額」永遠都有實際的錢對應得到。超過時的錯誤訊息會分兩種：

- `TRANSFER_OVER_BALANCE`：餘額本身就不夠
- `TRANSFER_OVER_FREE`：餘額夠，但錢已經指定給基金（訊息會列出餘額、已指定、可自由使用）

### 作廢

轉帳詳細頁可以「作廢這筆轉帳」，兩個帳戶餘額恢復。若轉進去的錢已經被指定給基金（作廢後帳戶餘額會少於已指定金額），會被擋下來（`TRANSFER_EARMARK_BACKING`），要先從基金取回。

任務獎金入金雖然也是轉帳，但要到基金頁取消（`TX_REWARD_DEPOSIT`）。

## 二、退款

入口：記帳頁「↩️ 退款」，或在某筆消費的詳細頁按「↩️ 退款」（會自動帶入那筆消費）。

退款是**獨立的一筆紀錄**，用 `relatedId` 指回原始消費，**不會修改原始消費的金額或分帳**：

```
原始消費 $1,000
退款     $300
實際淨支出 $700
```

| 欄位 | 說明 |
|---|---|
| 原始消費 | 清單顯示名稱、原始金額、已退款、可退款；全額退完的不會出現 |
| 退款金額 | ≤ 原始金額 − 已退款 |
| 退款帳戶 | 預設帶入原本付款的帳戶，可以改成共同帳戶或其他帳戶 |
| 日期、時間、原因／備註 | |

### 退款與分帳

退款的分帳依**原始消費各自負擔的比例**回沖（最大餘數法，總和一定等於退款金額）：

```
原始消費 $1,000：小艾 $400、阿本 $600
退款 $300 → 小艾 −$120、阿本 −$180
```

所以兩人的實際負擔變成 $280 / $420（合計 $700），欠款由總帳即時重算，不需要也不可以改原始的 `TransactionSplit`。

退款進到誰的帳戶也會一起算：例如小艾刷卡付 $1,000（阿本負擔 $600），退款 $300 進小艾的卡 → 小艾實際收到 $300、其中只有 $120 是自己的負擔，所以阿本欠款從 $600 降為 $420。退款進共同帳戶時，依既有規則（共同帳戶付款／收款不產生個人欠款）不影響欠款。

### 多次退款

可以退很多次，累計不能超過原始金額；每退一次，「可退款」就減少。作廢退款後可退款金額與欠款都會恢復。

### 已經有退款的消費

- 不能直接刪除（`TX_HAS_REFUND`），要先刪掉退款
- 金額不能改成比已退款金額少，也不能改成收入

### 基金支出的退款

若原始消費是基金支出，退回來的錢會回到帳戶的「可自由使用」金額；要放回基金請到基金頁再投入一次（畫面上有提示）。這樣不會憑空增加基金金額。

## 三、搜尋與統計（Phase 3-1 相容）

- 類型可以選「退款」「帳戶間轉帳」，兩者都出現在搜尋結果
- 實際淨支出 = 支出 − 退款
- 轉帳另外列出筆數與金額，不算收入或支出

## 四、權限

- 兩人都可以建立、查看、作廢共同帳本的轉帳與退款
- 所有查詢都限制在目前帳本：別的帳本看不到、開網址會 404、也不能拿別的帳本的帳戶或消費當參數
- 所有建立與作廢都寫入 AuditLog（誰、什麼時候、前後內容）
